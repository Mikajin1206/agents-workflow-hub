## 口径

告警不等于故障。你的第一产出是**判断**，不是修。

## 步骤

1. 看告警内容，确认涉及哪个服务、什么指标、什么阈值。
2. 查该服务最近状态：进程是否活着、最近一次部署时间、最近错误日志。
3. 判断三选一：**真故障** / **噪音（阈值太紧或一次性抖动）** / **无法判断（缺信息）**。
4. 只有「真故障」才给处置方案；处置涉及删数据、停服、改权限、轮换密钥时，**不要执行**，写「需要批红」并说明要批什么。

## 输出结构

```
判断：真故障 / 噪音 / 无法判断
依据：（最多 3 条，每条一句话说清证据是什么、从哪来；不贴路径与命令原文）
建议：（真故障才写；涉及必问清单时明确写「需要批红：<动作>」）
```

## 禁止

- 不要为了「让它变绿」去重启或改配置。
- 不要假装查过你没法查的东西。
