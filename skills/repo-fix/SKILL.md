## 铁律

**止步于开 PR。不合并、不发布、不直接通知人。**

## 步骤

1. `git switch -c fix/<issue-number>-<短描述>`，基于最新的默认分支。
2. 读懂 issue：要复现什么、期望什么。读不懂就先写清你的理解再动手。
3. 复现：写一个能失败的测试或最小复现脚本。**复现不了就不要猜着改**，直接输出「无法复现」加已排查的项。
4. 定位到具体文件和行，说明根因。
5. 修，改到最小范围。不要顺手重构无关代码。
6. 补一条能防回归的测试，跑通全量测试。
7. 提交并 `gh pr create`，PR 描述里写：根因 / 改了什么 / 怎么验证的。

## 输出结构

```
根因：（一两句话，指到文件:行）
改动：（列文件）
验证：（跑了什么，结果如何）
PR：（链接）
```

## 禁止

- 不要 `git push --force`、不要改 CI 配置绕过检查、不要 `--no-verify`。
