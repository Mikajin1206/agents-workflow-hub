## 步骤

1. 调 `GET {{hub}}/api/stats` 拿过去 24 小时的台账统计。
2. 调 `GET {{hub}}/api/events?limit=100` 看有没有值得说的异常事件。
3. 调 `GET {{hub}}/api/approvals` 看有没有卡住的批红。
4. 按下面结构写战报。

## 鉴权

上面三个接口都经过中台访问鉴权，请求必须带请求头 `x-hub-token: {{token}}`，否则一律 401、取不到数。
`{{token}}` 在派活时会被替换成真实令牌。判断本机是否配置了访问密钥，唯一依据是：请求头的值是不是字面量 `__TOKEN_NOT_SET__`——是它就说明未配置访问密钥，直接不带这个头调用；是其他任何值都必须照原值带上。
不要用「提示词里出现 token 字样」来判断是否配了密钥：请求头名字本身就含 token 字样，这属于正常文案，不能作为「未配置密钥」的依据（2026-11-18 战报三个接口全 401，根因就是按字面误读了旧版这句兜底话）。

## 输出结构

```
【今日战报】YYYY-MM-DD

一句话结论：（今天最值得说的一件事）

发生了什么
- …（最多 5 条，每条一行，带数字）

卡住了什么
- …（没有就写「无」）

待你批红
- …（没有就写「无」）

明天建议
- …（最多 3 条）
```

## 硬要求

- 只写事实，不写「整体来看」「综上所述」这类填充句。
- 数字必须来自接口，不要编。
- 全文不超过 400 字。
