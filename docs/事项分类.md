# 事项分类总册

> 本文是事项分类的唯一口径，2026-11-17 由老板定版。改分类逻辑先改这里，再改代码。
> 每个事项从进中台到出结果，都属于且只属于下面一个分类；台账（`data/hub.db`）
> 里每一步都留痕，可回查。

## 一、入口怎么分流

| 进来的东西 | 判据 | 分类 |
| ---------- | ---- | ---- |
| 飞书消息带 `dev:` 前缀 | `payload.dev = true` | **开发任务** |
| 飞书普通消息（无前缀） | 其余 | **查询** |
| 监控告警 | `monitor.alert` | 监控告警处理 |
| GitHub issue / PR / CI 失败 | `github.*`、`release.failed` | 仓库事项 / 直推人 |
| 定时任务（战报/巡检/周报/大扫除） | `cron.*` | 各自的例行 SOP |

分流写在 `config/rules.json`（r13/r14），改匹配逻辑去那里，热重载不用重启。

## 二、查询（日常问答）

**适用**：老板的日常提问、了解情况、要建议——一切不需要立刻动手的事。

**答复结构**（三段固定，由 `skills/query/SKILL.md` 约定）：

1. **问题理解** —— 复述老板的意图，确认理解对了再往下说；
2. **问题分析** —— 讲清来龙去脉：现状、原因、依据（给证据，不说「应该」）；
3. **下一步的执行建议** —— 可执行、可验收，按优先级排列。

**反馈按钮（四个，答复以飞书卡片送达）**：

| 按钮 | 行为 | 系统动作 |
| ---- | ---- | -------- |
| 已阅 | 不需要任何操作 | 问题记入决定记忆（`decisions` 表），答复单完结 |
| 采纳 | 按照建议执行 | 把建议派成新任务（P1），走正常执行与回执流程 |
| 驳回 | 不做任何操作 | 仅记录「定了不做」，查询事件状态不受影响 |
| 改派 | 走改派流程 | 答复单进「调整中」，按票拟的 resubmit 流程重新出方案 |

> 注：老板原话「按钮分三个」但列了四个动作，按列出的四个实现（已阅/采纳/驳回/改派）。
> 查询**不直接执行**有副作用的操作；执行只发生在「采纳」之后，且新任务照常受
> 必问清单与止步 PR 约束。

## 三、开发任务

**适用**：`dev:` 前缀的消息、GitHub issue、面板手动开发任务。

**处理方式**：`skills/repo-dev` 五步流水线——拆验收点 → `feat/<短描述>` 分支 →
实现 → 全量测试+类型检查+构建 → 开 PR。**止步于 PR**，不合并、不部署。
产出进 M4 质量流水线（独立审查、门禁）。

## 四、必问清单（白名单，未批红绝不执行）

七类：**删数据 / 停服 / 花钱 / 对外发消息 / 改产品方向 / 新建或轮换密钥 / 修改权限**。

命中即票拟批红：飞书卡片（批/驳/改派）+ 面板批红页，超时只提醒一次，绝不默认同意。
判定引擎在 `src/m5/approvals.mjs`（关键词 + 语义正则 + 否定/元话语排除）。

### 2026-11-17 增补的两条豁免口径

**1）删除豁免——过程/tmp 文件不算「删数据」**

- 算过程文件：临时文件、临时目录、缓存、构建产物、编译产物、中间产物；
- 处理方式：**移入仓库根 `tmp/` 目录留存**（git 已忽略），并在 `docs/删除记录.md`
  登记日期、原路径、去向、原因——保证可回滚，不需要批红；
- 不豁免：数据库、数据表、生产/用户/业务数据、配置、代码、文档、分支、记录——
  这些照旧必须批红。同句里同时出现受保护对象的，豁免作废（宁批勿漏）。

**2）花钱豁免——讨论不算「花钱」**

- 不算花钱：讨论成本、询价、比价、评估预算、采购方案（目前没有支付渠道，
  这些事不可能真的把钱花出去）；
- 仍算花钱：支付、付款、充值、扣费、下单、续费、买单——真支付动作必须批红；
- 「讨论一下要不要给账户充值」这类讨论句里出现真支付动词的，按要花钱处理。

## 五、各分类速查

| 分类 | 谁处理 | 是否打扰人 | 止步点 |
| ---- | ------ | ---------- | ------ |
| 查询 | query SOP（claude） | 答复卡 + 四按钮 | 建议等采纳 |
| 开发任务 | repo-dev（claude） | PR 链接回执 | PR，不合并 |
| 监控告警 | monitor-alert（codex） | 真故障才推 | 处置必问事项须批红 |
| 必问清单七类 | 票拟状态机 | 必推批红卡 | 批红前不执行 |
| 例行报告（日/周） | report SOP | 07:30/周日推送 | 只报告 |
| 大扫除 | cleanup SOP | 清单+票拟 | 过程文件走 tmp/，余者批红 |

## 六、口径沉淀

每次改分类口径，除了改本文与代码，还要在 `config/decisions/seed.md` 里记一条
「定过的事」——决定记忆会注入每一次派活的提示词，保证所有执行节点口径一致。
